1 The one idea behind everything

JavaScript does not wait for slow things (like the internet). It runs the next line immediately. That single fact causes 90% of the confusion.

// Asking the internet for data takes TIME (e.g. 2 seconds)
const data = fetch("https://api.example.com/user");
console.log(data);  // runs IMMEDIATELY — internet isn't done yet!
console

See? You get Promise {pending} — a "receipt", not the actual data. JS didn't wait. That's the whole problem await solves.

2 The restaurant analogy

You order food. You don't freeze at the counter until it's ready — you sit down, the kitchen works in the background, and you're called when it's done.

you 🧑‍🍳 kitchen (the API) your table 🧍 ... 
async function dinner() {
  orderFood();                        // 1. place order
  const food = await kitchen();   // 2. wait HERE (but sit comfortably)
  eat(food);                           // 3. only runs once food arrives
}

4 The 3 reasons it "sometimes doesn't work"

    
This is the part nobody explains. Here's exactly why your code is unpredictable.

    

      

        
🫥

        

          
Reason 1 — You forgot await

          
Without it, you hold the receipt (a Promise), not the data. user.name becomes undefined and crashes — but only sometimes, because timing shifts.

        

      

      

        
🔀

        

          
Reason 2 — Things finish out of order

          
Async code doesn't run top-to-bottom. A fast request can finish before a slow one you started earlier. If line B secretly depends on line A, it works on a good day and breaks on a slow one. (This is a "race condition".)

        

      

      

        
🧯

        

          
Reason 3 — No error handling

          
The Wi-Fi drops, the API 500s — the Promise rejects. With no try/catch, your whole function silently dies. Works on good internet, "randomly" fails on bad.

        

      

    

  


  
  

    
5 The pattern that always works

    
Memorize this shape. async on the function, await on every slow thing, try/catch around it.

    

      
async function getUser() {
  try {
    const res  = await fetch("/api/user");   // wait for the response
    if (!res.ok) throw new Error(res.status); // catch bad responses
    const user = await res.json();          // wait for parsing
    console.log(user.name);                  // ✅ real data, guaranteed
  } catch (err) {
    console.log("Something went wrong:", err); // ✅ never crashes silently
  }
}

      
Bonus — running things at the same time. If two requests don't depend on each other, don't await them one-by-one (slow). Start both, then await together:

      
// 🐢 Slow — 2s + 2s = 4s total
const a = await getA();
const b = await getB();

// 🚀 Fast — both run together = 2s total
const [a, b] = await Promise.all([getA(), getB()]);

    

  


  
  

    
6 Spot the bug

    
Why does this print undefined? Pick the fix.

    

      
async function show() {
  const res  = fetch("/api/user");   // 👈 line in question
  const user = await res.json();
  console.log(user.name);              // prints: undefined 😕
}

      
      
      
      
      

        ✅ It's A. Without await, res is a pending Promise, not the response. Calling .json() on it gives garbage, so user.name is undefined. The instant you add await fetch(...), res becomes the real response and everything works — every time, not just sometimes.
